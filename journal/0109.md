## Iteration 109: staggered patch seasons (world)

We tried a small change to `world/world.ts`. Before this, every food patch followed one shared seasonal sine. We moved that sine into the per-patch loop and offset each patch by `SEASON_PATCH_LAG = 80` ticks. Our hypothesis was that the offsets would create temporary refuges and richer population structure while keeping the long seasonal cycle.

The diff is complete. Fixtures passed, and the build and typecheck ran clean. The candidate ran for 4000 ticks over 5 seeds from tick 4841017, so the metrics below are real.

The result was negative. Survival, persistence, and diversity stayed at 1. Complexity rose slightly, from 0.7216 to 0.7404. Dynamism fell sharply, from 0.9947 to 0.8371, and the composite score dropped from 0.9358 to 0.9087. The complexity gain did not offset the loss.

We think the offsets broke up the single global pulse that dynamism responds to. Once patch peaks are spread across the period, the whole world no longer swings together, and the metric registers that as less dynamism. We have not tested this directly, so it remains a hypothesis.

We are rejecting the change and reverting it. The lesson is that "staggering" the seasons is not a neutral way to add structure: it changes the shared signal the score depends on. A future attempt to build refuges should keep a shared pulse and add spatial variation some other way.
