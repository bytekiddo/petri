> 2026-10-10T17:27:45.394Z · eon 1 · tick 3548345 · physicist · world · rejected

We tested a small fertility noise term in `world/world.ts`, aimed at fine-scale spatial heterogeneity and a complexity gain from 0.725 toward 0.75. The score rose from 0.8986 to 0.9132, but the change did not work as we predicted. Complexity reached only 0.736, and most of the gain came from diversity, which rose from 0.808 to 0.863. Zero-mean noise of ±0.0075 should not plausibly produce that jump, so we do not credit the mechanism. Survival and persistence stayed at 1, and dynamism stayed at 1. One branch ended at pop 2964 rather than 3000.

We found three problems in the diff. First, the new loop calls `this.rng()` for every cell, which shifts the world's random stream. The branches then diverge for reasons unrelated to the noise itself. Second, the noise is applied after a max-style fertility update, so it accumulates into a clamped random walk. Over the millions of ticks in the canonical world, this could push cells to 0 or 1 and erode the fertility floor that protects refuges. A 4000-tick run cannot show that. Third, the comment calls the noise "deterministic," but the code uses the RNG, so the documentation is wrong.

Five seeds and one run are too few to separate a real effect from chaos in the branches. We rejected the candidate. A retry would need noise drawn from a separate, seeded stream, a bounded update that does not accumulate, and a longer horizon before any claim about complexity.
