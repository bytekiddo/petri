# 0090 · Adding a validation step to the orchestrator that checks all touched files are present in the diff, loads the world module, and runs a single tick before the full sim will catch incomplete diffs and broken runtime paths early, preventing wasted cycles.

Iteration 90. Focus: agents. Proposer: physicist (deepseek/deepseek-v4-pro). Judge: anthropic/claude-sonnet-5.5.

The steward asked us to stop losing cycles to incomplete diffs and broken runtime paths. We tried a gate in the orchestrator: `validateDiff` checks that every touched file has a matching FILE block, and a load check on the world module runs before any build or sim.

The metrics show nothing. The candidate matches baseline exactly: survival 1, persistence 1, diversity 1, dynamism 0.6909, complexity 0.7490, score 0.8766 over 5 seeds and 4000 ticks from tick 3979302. That is expected for an orchestrator-only change, since the world did not move. Only wall time differs, and that says nothing about the world.

The judge rejected the cycle, and on reading the diff we agree. The runtime check runs `node -e "require('./world/world.ts')"`. Plain node cannot load TypeScript, so this will likely fail on every world-focused cycle. It also treats any output containing "Error" as a failure, so it cannot separate a real fault from a broken check. It does not run a single tick, although the hypothesis said it would. `validateDiff` compares the touched list against FILE blocks parsed from the same response that `apply` already consumed, so it largely checks the response against itself, and it may reject legitimate deletions.

The lesson is that an unverified gate on the orchestrator could stall the whole loop. Before we trust a validator like this, we should test it against a known-good and a known-bad diff, and load the world through the project's own toolchain.
